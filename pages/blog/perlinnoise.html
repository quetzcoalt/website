Perlin Noise - Terrain Generation Algorithm

It's a type of gradient noise developed by Ken Perlin in 1983 as a result of his frustration with the "machine-like" look of CGI at the time.

It's mainly used for procedural generation of terrains in video games.

How Perlin Noise Works?

1- Define a grid

2- At every corner of the grid, assign a unit vector (a vector of length 1) → These gradients influence the output noise values

3- Calculate the noise for a point:
Given an input point (x, y), Perlin Noise returns an output ranging from 0 to 1. For example:

function noise(x: number, y:number): number {}

4- Identify which grid square the input point lies within. The corners of the square are integers, while the input point's coordinates are floats.

So we start by getting the values of the corners of the square we are in:

// The left top and bottom corners
    const x_l = Math.floor(x) & 255;
    const y_t = Math.floor(y) & 255;

    // The right top and bottom corners
    const x_r = (Math.floor(x) + 1) & 255;
    const y_b = (Math.floor(y) + 1) & 255;

We then get the fractional grid coordinates:

// Fractional x relative to the left side
    const xf_l = x - x_l;

    // Fractional y relative to the top side
    const yf_t = y - y_t;

    // Fractional x relative to the right side
    const xf_r = x - x_r;

    // Fractional y relative to the bottom side
    const yf_b = y - y_b;

5- Compute the dot product between the the hash of the corner's gradient vector and the vector pointing from the corner to the input point.

The dot product is defined mathematically:
A⃗.B⃗=∣A∣∣B∣  cos(θ)\vec{A}.\vec{B}=|A||B|\;cos(\theta)A.B=∣A∣∣B∣cos(θ)

Or:

A⃗.B⃗=AxBx+AyBy\vec{A}.\vec{B}=A_xB_x+A_yB_yA.B=Ax​Bx​+Ay​By​

We use the hash of the gradients at each corner of the grid so they appear random to avoid visual artifacts. And true randomness can be computationally expensive and non-deterministic. That's why we use a deterministic pseudo-random approach by employing:

  • A fixed permutation table to define a pseudo-random sequence.
  • A simple hashing function to select gradients from the table based on input coordinates.

We define the permutation table and hashes as follow:

let permutation: number[];

    for (let i = 0; i < 256; i++) {
        this.permutation[i] = i;
    }

    const p = [...permutation, ...permutation];

We also duplicate the permutation table to handle edge cases when we access gradients.

This array is later shuffled to ensure variation.

function shuffle(permutation: number[]) {
        for (let i = permutation.length - 1; i > 0; i--) {
            const j = Math.floor(Math.random() * (i + 1));
            permutation[i], permutation[j]] = [permutation[j], permutation[i]];
        }
    }

For a grid cell containing the input point (x, y) we use the permutation table to compute hashes for each corner:

const a = p[p[x_l] + y_t];
    const b = p[p[x_l] + y_t];
    const c = p[p[x_r] + y_b];
    const d = p[p[x_r] + y_b];
  • a, b, c, and d are the hashes for corners A, B, C and D respectively.

Here we get the point from duplicating the permutation table. For example, in p[p[x_l] + y_t]; the value of p[x_l] + y_t can exceed 255 and we get an error in a table of length 256.

This hashing ensures:

  • Each corner of the grid is mapped to a gradient in a way that appears random.
  • The gradients vary smoothly and predictably as the input point moves.

Using random gradients for each corner would result in discontinuities when moving across grid boundaries.

In conclusion:

  • Permutation Table: Acts as a source of deterministic pseudo-randomness for gradients.
  • Hashing: Maps input coordinates to gradients, ensuring smooth transitions and consistent outputs.
  • Repeatability: By using the same permutation table, the same inputs always produce the same noise values, which is crucial for applications like terrain generation.

And then we write the function to compute the gradient vector. The grad function simulates the dot product between:

  1. A gradient vector defined by the hash.
  2. A distance vector (x, y, z), representing the offset of the point from the grid corner.

There are two functions.

function grad(hash: number, x: number, y: number, z: number) {
        const h = hash & 15;
        
        const u = h < 8 /* 0b1000 */ ? x : y; 
        
        let v;
        
        // expanded it for readability.
        
        if (h < 4 /* 0b0100 */)
            v = y;
        else if (h == 12 /* 0b1100 */ || h == 14 /* 0b1110*/)
            v = x;
        else v = z;
        
        return ((h & 1) == 0 ? u : -u) + ((h & 2) == 0 ? v : -v);
    }

A step by step breakdown:

  • Take the least significant 4 bits of the hash.
int h = hash & 15;
  • Choosing the first component u
    • If the most significant bit of h is 0, choose u = x, otherwise u = y;
const u = h < 8 /* 0b1000 */ ? x : y;
  • Choosing the second component v
    • The selection of v depends on the first two bits of h (bits 1 and 2):
      • If both bits are 0, v = y;
      • If both bits are 1, v = x;
      • otherwise, v = z;
if (h < 4) v = y; 
    else if (h == 12 || h == 14) v = x; 
    else v = z;
  • Setting signs for u and v
    • The last two bits of h (bits 0 and 1) determine the signs:
      • If bit 0 is 0, u is positive; otherwise, u is negative.
      • If bit 1 is 0, v is positive; otherwise, v is negative.
return ((h & 1) == 0 ? u : -u) + ((h & 2) == 0 ? v : -v);
  • Example:
    Let
  • hash = 0b1101 (13 in decimal)
  • x = 0.5, y = 0.2, z = 0.8.

Compute h = hash & 15:

  • h = 0b1101

Select u:

  • h < 8 is false
    • So: u = y = 0.2

Select v:

  • h < 8 is false
  • h === 12 or h === 14 is false
    • So: v = z = 0.8'

Determine the signs:

  • h & 1 = 1, then u is negative.
    • So u = -0.2
  • h & 2 = 0, then v is positive.
    • So v = 0.8

Compute and return:

  • u + v = -0.2 + 0.8 = 0.6

The gradient vector is chosen based on the least significant 4 bits of the hash value:

hash & 0xf

Those 4 bits specify the direction and the sign for the gradient.

Hash Value (hex)Gradient VectorExplanation
0x0 (0000)(1, 1, 0)Both x and y are positive; z is zero.
0x1 (0001)(-1, 1, 0)x is negative, y is positive, z is zero.
0x2 (0010)(1, -1, 0)x is positive, y is negative, z is zero.
0x3 (0011)(-1, -1, 0)Both x and y are negative, z is zero.
0x4 (0100)(1, 0, 1)x is positive, z is positive, y is zero.
0x5 (0101)(-1, 0, 1)x is negative, z is positive, y is zero.
0x6 (0110)(1, 0, -1)x is positive, z is negative, y is zero.
0x7 (0111)(-1, 0, -1)x is negative, z is negative, y is zero.
0x8 (1000)(0, 1, 1)y is positive, z is positive, x is zero.
0x9 (1001)(0, -1, 1)y is negative, z is positive, x is zero.
0xA (1010)(0, 1, -1)y is positive, z is negative, x is zero.
0xB (1011)(0, -1, -1)y is negative, z is negative, x is zero.
0xC (1100)(1, 0, 0)x is positive, y and z are zero.
0xD (1101)(-1, 0, 0)x is negative, y and z are zero.
0xE (1110)(0, 1, 0)y is positive, x and z are zero.
0xF (1111)(0, -1, 0)y is negative, x and z are zero.

  • Each case corresponds to
    • a simple gradient vector like (1, 0, 0) or (-1, 0, 0).
